# Slice friction log

The slice in [`samples/slice`](../samples/slice) tests whether the library holds up inside a real roguelite, played headlessly by `cantrip sim`. This log records every place where building it needed a workaround, C# the content could not replace, or a surprise. Each entry is classed as a **language gap**, an **API gap**, a **defect**, or **fine as host code**.

## Found while building the first cut

1. **Defect, fixed: the Godot adapter's legal targets ignored `targetable`.** `CantripRuntime.GetLegalTargets` listed every living actor on the other side, while `CardRuntime.Play` filters candidates through the `targetable` channel. With a taunt or stealth on the board, a UI would have highlighted targets that the play then refused as `invalid_target`. The adapter's `CanPlay` also checked `energy` whatever the card was priced in.
2. **API gap, fixed: "what can I play, and at what?" was not in the core.** The bot had to rebuild it from `CostOf`, `CostResourceOf`, `IsXCost`, the `unplayable` tag and `Definition.Word("target")`, duplicating the adapter, which is how the adapter's copy had drifted from `Play`. `CardRuntime` now has `CanPlay`, `LegalTargets` and `TargetMode`; `Play` resolves targets through the same code, and the adapter and the bot call them, which fixed both defects in item 1.
3. **API trap, documented: `entity.Get("Burn")` reads 0.** In content, `enemy.Burn` is the status's counter. From C#, `Entity.Get` only reads stats, so the same name silently gives 0, and the bot's first scoring function counted no Burn at all. I first filed this as a missing helper, but `Entity.CounterOf("Burn")` already existed and does exactly what content does, duration statuses included; I had not found it. So the gap was discoverability: `Get` now says in its documentation that a status is not a stat and points to `CounterOf`, the C# guide (docs/csharp.md) shows both, and the bot uses it.
4. **Fine as host code, for now: the run.** Hp carries over by itself, since the player entity persists. `AddCard` and `AddRelic` between battles, and `Execute("heal N")` for a rest, were all that was needed. What the host does own is the map, the encounter list and reward pools: `encounter` has no meaning yet, and loading one is error CT0113, so the tower is a C# array. Gap 17 in [coverage.md](coverage.md) stays open, but this slice did not suffer for it. Revisit once a run needs rules that content should own, such as events between battles or relics that act on the map.
5. **Not a gap: a threshold on a status's own stacks.** Three Chill should become Frozen. The first cut did it in a content verb, `chill`, which any `apply Chill` written elsewhere would have skipped. A status can watch its own host instead: `on status_applied(Chill, target:owner):` on Chill checks the count and freezes, whoever applied it. That works on the very first application only because a listener that becomes active during an event hears that event (gap 6 in [coverage.md](coverage.md)), so the slice's tests pin the first-application case; if gap 6 is ever settled by changing that default, this is what will tell.

## What went well

- Every DSL test for the slice passed on the first run, and lint was clean apart from one intended loop note on Frozen.
- The runtime already supported several battles in a row with one runtime: `StartBattle` counts battles, cards return to the draw pile, and non-persistent statuses clear.
- Snapshots are cheap enough to drive a bot that looks one card ahead through 500 whole runs, and every run replays exactly from its seed. [Performance](stability.md#performance) has the command and a current measurement.
