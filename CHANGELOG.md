# Changelog

Versions follow [semantic versioning](https://semver.org). While the major version is 0, any release may change the API, the language or the save format; [docs/stability.md](docs/stability.md) says what that means in practice. Each release's notes on GitHub are its section here.

When a release changes any of the following, its section says so under that name:

- **Breaking changes**: anything that can stop a game's code, its content or its CI working as before, including the Godot node's methods, signals and dictionary keys.
- **Save format**: whether saves made with the previous release still load.
- **Same-seed results**: whether the same content, seed and inputs still play out the same way.
- **Bot behaviour**: whether `cantrip sim`'s bots play a scenario the same way, so that a report whose numbers have moved says why.

## [Unreleased]

Work towards 1.0. Three audits went through the C# API, the Godot addon's script surface and the language and save format, asking of each frozen thing: would we regret this in five years? What follows is the answers so far. Everything here is a change that stops being free once 1.0 is out.

### Added

- **`clock turns` or `clock ticks` in a `ruleset` block**, so content says which clock it is written for. A length in the other clock's units — a cooldown, a `for`, an `in N ...:` delay, an `on every ...:` interval — is then error **CT325** at lint, and a runtime built with the other clock refuses as it is built. Both halves used to fail differently and neither said so: `on every 1s:` in a turn game registered nothing at all, in silence, while `apply Weak 1 for 3s` in the same game threw only when the line ran. Content that says nothing is unchanged and still runs on turns.
- **`new_listeners: hear_the_event` or `miss_the_event` in a `ruleset` block**: whether a listener that comes into play during an event hears that event. The default is `hear_the_event`, which is what it has always done, so nothing moves; content that would rather a minion did not hear its own summoning says so and drops the `not target:self` filter. Both are real rules in real games, which is why it is a setting rather than a fix. This closes [coverage](docs/coverage.md) gap 6 and lets the default move later without breaking anyone.
- **A save says what it is and who made it.** `GameSnapshot.WrittenBy` is the version that wrote it, `MinimumReader` the oldest build that can be trusted with it, and `RngGenerator` the generator its random state came from. `GameSnapshot.ReaderNeededBy` answers "can this build read this save?" before a restore, so a game can tell the player it needs a newer version rather than catch an exception.
- **`into` binds what `heal` and `block` really did**, as it already did for `deal` and `attack`: `heal 30 into restored` is what was restored after the heal stopped at full health. **`shuffle ... into <zone>`** now puts the cards where it says; `shuffle hand into discard`, a form the reference already listed, used to shuffle into the draw pile whatever the clause said.
- **Every member of `IEffectHost`, `IChoiceProvider` and `IDescriptionLocalizer` has a default implementation**, as does `IGameClock.TryConvert`, so a game implements only the part it has an opinion about. `EffectHostBase` and `EnglishDescriptions` stay as conveniences. `IGameClock.Now`, `Advanced` and `Restore` deliberately have none: the only defaults available are a clock stuck at zero, an event that never fires and a restore that quietly keeps the wrong time. [Stability](docs/stability.md) now records that a member added to one of these seams with a default is additive rather than breaking, and both the unit tests and the Godot headless suite prove the dispatch inside the engine a game ships on.
- **A `board` declaration**, so a battle can be fought on more than one row. A board is a rectangle of `lanes` across and `ranks` along the facing axis, both counting from 0, with a `facing`/`shared` switch, `manhattan` or `chebyshev` as the only geometry knob, `on_vacated gap` or `close_ranks`, and `lane_word`/`rank_word` for a game that calls a lane a floor. Content declares any number of boards by name and a game picks one per battle with `StartBattle(board: "Train")`; a test picks one with `board "Train"`. Content that declares none is played on `lanes 1, ranks unbounded, facing, manhattan, gap` — today's board, spelled out — so nothing written before this moves. A board is content rather than something a game makes up at runtime, because the linter has to know how deep one is to say that `it.rank <= 3` on a three-rank board reaches everybody. `samples/board` is a Monster Train style train, three floors tall, in CI.
- **`ends: last_enemy` or `ends: called` in a `ruleset` block**, and `CardRuntime.EndBattle(won)` — `EndBattle(won)` on the Godot node. A battle has always been won the instant the last enemy was gone, which is right for a fight the engine lays out once and wrong for every fight that arrives in waves: the board is empty every few seconds by design, so the first gap between two waves wins it, and the only way to hold a real-time fight open was an untargetable enemy parked off the board that every count, every `deal to enemies` and every "is the line clear" question had to remember. Under `ends: called` an empty board is just an empty board; the party falling still ends the fight, because that is the same rule in every game. `last_enemy` is the default, so nothing written before this moves.
- **`CardRuntime.Place(actor, lane, rank)`**, and `Place(actor_id, lane, rank)` on the Godot node: content's `target.rank = 0` from the game that owns the fight above it. It raises `moved`, `before_moved` refuses it, and a slot the board does not have is refused with the board's own name rather than clamped. A game that spawns its own waves had no call at all for this and placed every arrival by executing a string of content — which turned a typo in a lane number from a compile error into a runtime one, on a hot path.
- **`CardRuntime.AbilitiesOf(owner)` and `ReadyIn(ability)`**, and `CooldownLeft(ability_id)`, `GetTicks()`, `GetSeconds()` and `IsRealTime()` on the Godot node. A row of ability buttons with cooldown sweeps is the whole of a real-time interface, and from C# there was no documented way to list an actor's abilities or ask how much longer one had to wait: the answer was an undocumented `ready_at` stat that does not exist until the ability has been used once, so a front end had to find it by reflection and then know to read "absent" as ready rather than as zero seconds left. `GetTicks()` and `GetSeconds()` are the game's own clock — `TickDriver.TotalTicks()` is the driver's count, and the two part company the moment a save is restored.
- **`who.is_ready(Ability)` and `who.can_use(Ability)` in content.** `cast` fails a test when the ability is on cooldown or has nothing in reach, and there was no predicate either, so in a game whose whole design is about what you may not do yet, half the test surface had no words and the workaround was to write the test inside out. Two questions rather than one, because "still cooling" and "nothing to aim at" are different answers.
- **`SpawnEnemy` raises `created`**, the same event `create` raises, so content can meet an arrival. It is an announcement rather than a gate — the actor is already in the game — so a `before created:` listener cannot cancel a spawn the game has decided on. In a turn game a spawn happens once, before the battle; in a wave game it is the most frequent event there is.
- **`Num.ToLong()`**, beside `ToInt()` and `ToDouble()`. A `Num` is fixed-point rather than a `long` in disguise, so the cast cannot work, and a tick count is the one value that wants a `long` and not a rounded `int`.
- **A real-time section in [docs/csharp.md](docs/csharp.md#real-time)**, which had none: in 689 lines `TickClock` appeared once in a parenthesis, `clock ticks` never, and there was no example. And **[docs/godot.md](docs/godot.md#real-time)**'s thirteen lines are a page, with the whole of `TickDriver` — `Ticked`, `TotalTicks()`, `DroppedTicks()` and `Reset()` were undocumented — a statement that a stall **skips** time rather than replaying it, and a section saying that `Engine.time_scale` does not speed a Cantrip game up and what does.
- **[realtime/](realtime)** — *Emberline*, a forty-five second hold against waves on a tick clock: content, a headless C# host, a Godot front end driven from the engine's physics loop, 18 content tests, 25 host checks and 40 in-engine checks, all in CI. It is the first game built on real time, and [realtime/FINDINGS.md](realtime/FINDINGS.md) is what building it found.
- **`fallen`**, the dead of a side, beside `party` and `allies`. `heal` refuses a corpse and always will, so bringing one back is its own verb — and nothing could name its argument: `party` and `allies` hold the living by design, `target ally` and `target any` both want somebody alive, and `everyone where zone:dead` finds nobody. The in-combat raise every party roguelite ships could not be written at all, in a language that had the verb for it. `revive fallen.first 8` and `choose 1 from fallen as who` both work; C# gets `runtime.Fallen` and `State.Fallen(team)`, GDScript gets `GetFallen()`.
- **`CardRuntime.SetStat` and `ChangeStat`**, and the same two on the Godot node. There was no typed way to write a number onto an entity, so a game finishing its leader — a `speed` for `order: speed`, where an actor with none reads 0, takes its step last, and so draws the party's hand after everybody has acted — or spending gold in a shop built a statement and called `Execute`: `runtime.Execute($"lose {amount} gold")`, unchecked until it runs, to subtract an integer.
- **`CardRuntime.RemoveCard`**, the call the Godot node has had since the addon shipped. The same operation was a typed call on one side of the engine and a parsed string on the other, and only the Godot one was written up as a recipe.
- **`StartBattleOn(board, shuffle, draw_opening_hand)` on the Godot node**, and a **Boards** section in `docs/godot.md`, which had none. `CardRuntime.StartBattle(board:)` could always pick one; a Godot game with more than one `board` declared was stuck with the first. It is a method of its own rather than a third argument because a C# default is not a default in GDScript, and a third parameter would have broken every game that already calls `StartBattle`, at parse time.
- **`CounterOf` on the Godot node.** `Warden.Fervour` in content and `entity.CounterOf("Fervour")` in C# had no third spelling, so a status bar walked `GetEntity(id)["statuses"]` — every stat, tag and status built to answer one number — once per member per frame, and `GetStat(warden, "Fervour")`, which is what the DSL's own vocabulary suggests, answered 0 without saying why.
- **`board` is a `scenario` verb.** Which board a fight is fought on is part of stating the fight, and without it a game with more than one board could not be simulated the way it is played: the host would name a board the scenario could not.
- **CT336**, a warning for an `of` group that can never hold what the channel names — a pile of cards on a channel whose value belongs to an actor. A modifier that cannot match is worth saying out loud rather than leaving to a test that guessed the number.
- **A `hero` declaration**, so a game can have a party. A hero is an actor on the player's side that the game asks for input: `EntityKind.Actor`, `Team.Player`, on the board with a place, in `allies`, a legal target for a taunt. `abilities Smite, Bulwark` hands those over when the member is made, and `create Vestal` in content is how a mid-run recruit or a summon that *acts* arrives. The leader `CreatePlayer` makes is already a member, so **a party of one is every game written before this existed**, down to the random draws it does not make — `cantrip sim samples/slice` over 500 seeds is byte-for-byte unchanged. A summoned `actor` is deliberately **not** a member: a Monster Train or Hearthstone minion attacks from its own `turn_end` and must not acquire an input step nobody asked for. `samples/party` is four heroes with abilities, in CI.
- **`Party`, `CanAct`, `Pass` and `AddHero` on `CardRuntime`.** `Party` is the living members in the order they stand, derived every time it is asked and never stored, so a death or a swap mid-turn changes it with no bookkeeping. A member that is done passes; when the last one has, the enemies take their turn — so for a party of one `Pass` is `EndTurn`, down to the turn number and the state hash. `Entity.IsPartyMember` is what tells the four heroes from the Shiv golem.
- **An enemy says who it is going to hit.** `move "Cutthroat" at lowest hp enemies:` telegraphs a target as well as a move, using the selector grammar that already existed — `at random enemies`, `at lowest rank enemies` — so no new words. With no `at` the move aims at a living party member drawn uniformly; with one member there is nothing to draw and nothing is drawn. `enemy.intent_target` in content and `IntentTargetOf(enemy)` in C# are **recomputed on every read**, so a taunt applied mid-turn re-aims the telegraph with no event for a UI to have missed — and they agree with what the move does when it runs, because both ask one question of one rule.
- **`revive <who> [N]`**, and `CardRuntime.Revive`. `heal` refuses a dead target, deliberately and permanently, so there was no way at all to put a fallen member back on its feet. It raises `revived`, and does nothing to somebody who was never dead, so a card that reads "bring back a fallen ally" cannot quietly become a heal.
- **`grant Cleave to target` as a rule verb.** Granting an ability was something only C# and a test could do, which is what CT320's own message had been telling authors for two releases. It is one verb everywhere now: the test-only `grant` is gone, and `grant Smite` with nothing after it means the same to the rules as it meant to the test runner.
- **`party` and `leader` as names**, and `turns:` / `order:` in a `ruleset`. `party` is the living members; `leader` is a second name for `player`, for content that would rather say what it means.
- **`turns: initiative` in a `ruleset`**, so every combatant takes its own step in one order across both sides rather than the party acting and then the enemies. Each one's `turn_start` and `turn_end` fire at **its own step**, which is the natural reading of "at the start of your turn" and the order Darkest Dungeon uses; the round ends when every living combatant has taken one. **One round is still one `turn`** — `State.Turn` is the round number and the clock advances once a round in both modes — because `once per turn`, `on every N turns`, the history counters, the saved turn number and `sim`'s stall limit all key off it, and four heroes must not make it mean four things. With one member against one enemy the two modes play the same round, to the turn number and the hp. `turns: sides` stays the default. Under `initiative` the clock moves at the *start* of the round rather than after a side's turn has started, because combatants start their turns one at a time and there is no moment at which they all have; work that must survive a turn-start reset goes on `next turn:`, which fires at that actor's own step.
- **`order: speed`**, which sorts the turn order by the `speed` stat descending, ties broken by where combatants stand and then by id. `order: position` stays the default because it cannot move an existing game; `speed` orders the party under `sides` too, where it decides which member the engine offers first and the order they draw in. An actor with no `speed` reads 0, so a game that never writes the stat gets position order under another name.
- **`GameState.TurnOrder` and `GameState.HasActed`** — every living combatant on both sides in the order `initiative` runs them in, which is what an order bar draws, and whether one has taken its step. Both are read off the living every time they are asked and who has acted is remembered by id, so a death, a revival, a summon or a change of `speed` mid-round changes them with no bookkeeping and nothing extra in the snapshot.
- **The party on the Godot node**: `AddHero`, `GetParty`, `ActiveMemberId`, `CanAct`, `Pass`, `CanUse` and `Revive`, plus `PlayBy` and `PlayNamedBy` for a play a named member performs. `GetEntity` gains `party_member` and `acted`; `DescribeIntent` gains `target`, `target_name` and `line`. Nothing was removed and no existing signature changed: `PlayBy` is a method of its own rather than a third parameter on `Play`, because **a C# default argument is not a default in GDScript** — every parameter has to be passed — so a third one would have broken every `rules.Play(card, target)` written against a preview, at parse time. `Play` is not ambiguous for a party the way `GetHand` was: a card played with nobody named is played by whoever owns it.
- **`cantrip sim` plays a party.** Every bot asks each member that still has a step, plays with it and passes it; under `turns: initiative` that is the only thing that moves the round at all. A game with no `hero` has a party of one, is never passed, and plays the run it always did. `hero` is a scenario setup verb now, so a `scenario` can state a party, and `samples/party/sim.cantrip` fights two Brigands with one, in CI.
- **CT335**: `turns:` or `order:` written into a game that says `clock ticks`. Both say how a turn is shared out and a real-time game has none — `turn_start` and `turn_end` never fire there and the engine ignores the setting — so `turns: initiative` on a tick clock asks for an interleaved order that will never run, and says so nowhere. The CT325 case, with the same answer.
- **`Description.Against` and `Description.ToLine()`**, so an intent panel has one string: "Cutthroat → Vestal: Deal 8 damage and apply 2 Bleeding." `DescribeMove` now takes who the move is aimed at, so an intent's numbers go through that member's modifiers rather than the leader's, which for a party was simply the wrong actor.
- **`Play(card, target, performer)`**, for the second shape a party takes: one hand and one energy pool owned by the leader, with a member named as the one performing the play. The cost comes out of the pool, because that is whose cards they are; everything else is the performer's — `card_played`'s source, the damage, `source:` filters, that member's own statuses and modifiers. **`CanUse(ability)`** is `CanPlay`'s companion, and `LegalTargets` and `TargetMode` already answered for an ability, so one targeting UI serves both.
- **A save carries the party.** `GameSnapshot.PartyIds`, `ActiveMemberId` and `ActedIds`, and `IntentTargetId` and `IsPartyMember` on each actor. They went **into format 3 rather than starting a format 4**, because format 3 is not published: a save that lists no party is not an old format to migrate, it is a party of one, which is what it was.
- **The board has words for reaching across it.** `within(who, N)` is everyone on **either** side within N steps, including `who`; `lane(who)` and `rank(who)` are the row and the line across, on who's own side; `distance(a, b)` is how many steps apart two actors are by the board's metric. `adjacent(who)` stays same-side on purpose: on a facing board the two front ranks are one step apart, so a cross-side `adjacent` would have turned Hearthstone's Dire Wolf Alpha into a buff for the other team. **`within` with a unit — `within(x, 5m)` — is unchanged** and still goes to the game's `IEffectHost.TryCall`: slots are the engine's and metres are the game's, and the unit is what says which is meant.
- **`range` on a card, an ability or an enemy's move** (`move "Swing" range 1:`). `range 1` is melee and `range 2..3` is a bow that cannot shoot point blank, both measured in slots between whoever is using the action and the candidate. It is also a **modifier channel**, with the printed range as its base, so `modify range: set 1` on a status makes everything its holder points at melee — including a card that printed no range at all. The channel computes the far end and the near end follows it down, so a shortened longbow becomes a melee weapon rather than something that can no longer reach anything. A card's own `target … where` is deliberately **not** a channel: a card's printed reach is its own rule, not a stranger's to rewrite. Reach is decided in one function and nowhere else, so it cannot mean one thing for a card and another for an enemy's move.
- **Movement, as a member write.** `target.rank = 0`, `self.lane += 1`, `a.rank = b.rank`. There is no movement verb: `move` is taken by card zones, and `move target to rank 0` parses as two arguments and describes as "Move the target 0". An assignment arrives with four things already built — it raises `moved` with `kind`, `from`, `to` and the four numbers behind them; `before_moved` refuses it, which is knockback immunity with no new mechanism; `until turn_end: self.rank = 0` puts the actor back, because a place is two integers whose inverse is exact; and rollback and restore handle it because it is state. Assigning a slot somebody else holds swaps the two. A step that would leave the board stops at its edge, so a shove against the back wall leaves the unit against the back wall. `on_vacated close_ranks` now says `moved` for each survivor that steps forward, once the row has closed — `before_moved` is not asked there, because refusing half a closed row would put two actors on one slot. Any living actor may be moved: there is no permission system, and a unit that must not be pushed says so itself.
- **Rules text for all of it**, in the one phrase table a game can translate. `range 1` reads "Melee." and `range 2..3` "Range 2–3."; `target enemy where it.rank <= 1` reads "Targets an enemy in the front 2 ranks."; `target.rank = 0` is "Pull the target to the front" and `self.lane += 1` is "Move up one floor"; `deal 4 to lane(target)` is "to the target's floor" and `deal 3 to enemies in within(target, 1)` is "to every enemy within 1 step of the target". `lane_word` and `rank_word` are what let a train read "the front slot" and a grid "in this column" without either writing `text_override` on every card.
- **Lints for the words that decide nothing.** **CT330**: a `within` the engine will not answer the way it reads — a plain number, which counts slots, in a game that declares no board (a warning), or a length with a unit, which goes to the host (a note). **CT331**: `range` on something that points at nobody, so nothing ever reads it. **CT332**: a reach that decides nothing — as wide as the widest board this game declares, written backwards (`range 3..1`), or `range 0` at an enemy, which on a facing board is a slot no enemy ever stands on. **CT333**: `lane(...)` on a board one rank deep or `rank(...)` on a board one lane wide, where one actor stands on a slot so the row is that actor and nobody else. **CT0115** refuses a `range` that is not a number of slots, such as `range 5m`. **CT327** now also reports a *move* to a slot no board has, which stops at the edge of the board rather than failing.
- **`lane` and `rank` on an actor.** Ordinary members, so `target enemy where it.rank <= 1` is a card whose reach is the front two ranks and `lowest rank enemies` is the front. `rank` is the name; **`position` is an alias** that reads the same number and keeps working for the whole 1.x line, with note **CT329** suggesting the newer word, so it fades rather than flips.
- **A lane has a capacity, and a full one turns a summon away.** `create` puts a new actor in its maker's lane, on its own side, at the lowest free rank; if that lane is full nothing is made, `created` binds empty, and the trace says which lane was full. It is a refusal, the way `play` on an empty pile is, rather than an error that stops the card — which is Monster Train's floor capacity with no new concept in the language.
- **`GameState.Board`, `Distance`, `Neighbours`, `At`, `HasRoom`, `Assign` and `CloseRanks`.** Assigning a slot someone else is standing on swaps the two: total, deterministic and its own inverse, so a rolled-back action puts the board back exactly as it was.
- **Lints for a place.** A lane or rank no declared board can hold is **CT327**, which reports both ways it goes wrong: `it.lane == 2` on a one-lane board matches nobody, and `it.rank <= 3` on a three-rank board matches everybody and limits nothing. A `board` line the declaration cannot mean — `lanes 0`, an unknown `metric`, a property no board reads — is **CT0114**.
- **`target <side> where <filter>` on a card, an ability or an enemy's move.** A skill's own reach is written on the skill: `target enemy where it.position <= 1`, with `it` the candidate. It is an ordinary `where`, so a bare qualifier tests the candidate, and `self` is the action while `source` is whoever is using it. The alternative was a `targetable` modifier that had to name its own card — `card:Pike` — because a modifier on a card in hand otherwise binds every card played while it sits there, and there is no `card:self`. `samples/corpus`'s Pike drops the wart, Darkest Dungeon #6 moves from *Workaround* to *Works*, and [coverage](docs/coverage.md) gap 3 loses its `card:self` half and keeps its blocking-step half.
- **`Zones.WellKnown` and `Zones.IsWellKnown`.** The eleven zone names the rules use, and whether a string is one of them. Content and games may still use any other string, which is what makes the question worth asking: it is what lets a tool say that `"hnd"` is probably a typo without taking away a zone a game invented.
- **`CardRuntime` is `IDisposable`.** `Dispose()` lets go of the clock the runtime has listened to since it was built. It matters for a game that passes its own clock in `RuntimeOptions.Clock` and outlives a runtime that used it: two runtimes sharing one clock both keep resolving effects, and the clock holds the dead one alive. Nothing else is torn down, and a runtime that made its own clock needs no call.

### Changed

- **Four verbs refuse a name that is content, not three.** `replay Strike` ran a card's printed effect for nothing — no card, no cost, no play — which is the free lunch `copy`, `play` and `transform` were closed against in 0.1.0-preview.5. Now **CT320**, naming the way to a real card. `create` is refused the other way round: `create Poison 2` made two Poisons attached to nobody, which raised `created` and persisted into saves. Also **CT320**, naming `apply Poison 2 to <who>`.
- **`emit` cannot forge a built-in event (CT322).** `emit damaged 99 to player` dispatched to every `on damaged` listener although nothing was damaged, and no history counter moved with it: the event was forged and the record was not.
- **A clause a built-in verb does not read is an error (CT323).** The parser knows thirteen clause words, so one a verb did not read was dropped in silence: `block 8 for 2 turns` gave ordinary block that vanished at the next turn start, `apply Poison 3 at target` ignored the `at`, and `deal 5 against enemy2` hit the card's own target. Which verb reads which is now a table, in the reference and in the code, and the message names the clause that works. A flag after a comma is not a clause and is never checked, and neither is a verb content declares or a game registers in C#.
- **A bare percentage where a verb counts whole things is an error (CT324).** `apply Slow 40%` applied forty stacks while the card's own generated text said "Apply 40% Slow": a percentage stated to the player that the engine does not implement. Write the number, or a share of something: `target.max_hp * 40%`.
- **Enemy moves and the `attack` verb ask the `targetable` channel**, as a card's target already did, so a taunt and a stealth mean one thing wherever something is pointed at somebody. Area and random effects are deliberately unchanged, including inside a move: a taunt constrains what may be aimed at it, not what a blast reaches. This changes what existing content does. No sample moved, because none combined a taunt with an `attack` or a move; `samples/corpus` gains the test that was missing, and [coverage](docs/coverage.md) gap 3 loses the sentence about it.
- `Restore` refuses a snapshot whose two records of where a card is disagree, before it takes the running game apart, and refuses a random state from a generator this build does not have rather than feeding four numbers to a generator that reads them differently.
- **CT337**: machinery a turn drives, written into a game that says `clock ticks` — a `move`, a `pattern`, a `phase`, a `stacking duration`, a `decay … on turn_end`, an `until turn_end:`, a `next turn:`, an `once per turn`, a `reset_on turn_start`, or a `turn_start`/`turn_end` listener. CT325 already knew the stated clock and checked *lengths* against it, so `2 turns` under `clock ticks` was an error — while three enemies' worth of `move` and `pattern` blocks that could never run linted with zero errors, zero warnings and zero notes, and `apply Chill 3` was a permanent Chill. Every message names the real-time shape of the same idea and offers `clock turns` as the alternative.
- **CT338**: a `scenario` in `clock ticks` content, and **`cantrip sim` refuses such a folder**. It used to load one without a murmur and play it by calling `EndTurn` fifty times: the clock was a `TickClock` and nothing ever ticked it, so every `on every` listener was silent, every ability used once never came back and no battle could end — and the report said "40 battles reached the turn limit and never ended" under *What the content allows*, `hp lost 0.0` against enemies dealing seventeen damage every three seconds, and `50.0 turns` in a game with no turns, at exit 0. When to act in continuous time is a game's own frame loop, not a bot's.
- **CT339**: `cost` on an `ability`. It parsed, `CostOf` answered it and nothing spent it, so a designer got a free ability and a number that read like a rule. An ability is paid for in the seconds it makes you wait; the resource a `cost` would spend is reset by `turn_start`, which does not fire on a tick clock, so implementing it would have bought one poolful per battle and a quieter kind of wrong.
- **CT326 reads a listener** on an enemy, a card or an ability, as well as an enemy's move and a card's or ability's effect. A real-time enemy has no `move` at all, so its whole behaviour is written in listeners — which is to say the party guarantee was absent from the entire surface a real-time party game lives on, and `on every 2s: deal 5 to player` linted clean.
- **Real time is no longer marked experimental.** `docs/simulating.md`, `docs/stability.md`, `docs/writing-content.md` and `README.md` say what it is and is not, and what is still missing is named rather than glossed: there is no simulator for a real-time game, an ability cannot be gated on a resource, and the only speed control is `Tick(count)` driven by the game. README's first line no longer says Cantrip is for turn-based games.
- **`ActiveMember` is no longer null under `turns: sides`.** It is the member the engine would offer next — the first that has not acted — so one polling loop drives a UI in either mode: binding under `initiative`, a suggestion under `sides` that `CanAct` overrules, because there any waiting member may act. It used to be null there, so a host polling it got nothing to show. It is derived rather than stored, so a save no longer reads it back and it is no longer mixed into the state hash.
- **An enemy's move no longer prints "to the target".** `deal 8 to target` in a `move` reads "Deal 8 damage.", as the same line on a card always has, because the target is named beside the text rather than inside it.
- **`cantrip sim`'s `hp lost` and `hp_left` are the party's health between them**, not the leader's. For a party of one that is the number it always was; for a party it is the difference between "0.0 lost" and a fight the heroes nearly lost, because an enemy aiming at the lowest hp never touches the leader.
- **The battle is lost when no party member is alive, not when the leader dies.** A surviving summon does not keep the fight going, and a party that has lost its leader fights on. For a party of one the two readings are the same sentence, which is why nothing written before this notices.
- **`player` means the party's leader, and saying it where a member is meant is an error (CT326).** It is one entity and always will be — the one `CreatePlayer` made, the one that holds the run's relics and gold. In content that declares a `hero`, writing it inside an enemy's move or a card's or ability's effect is refused, because `deal 5 to player` in an enemy move would hit that one member however carefully the enemy telegraphed another, and it would do it in silence. `target`, `leader` and `party` are the three words that do what was meant, and the message names all three. Content with no `hero` is never reported, and `player` in a relic, a run's gold, a test or a scenario is never reported: there it is still the right word.
- **A turn's end discards every member's hand, and a battle's end tidies every member.** Both touched the leader only, so a hero's hand was never discarded at all and grew by a full draw every round, and a hero carried its statuses and its whole hand into the next battle. This changes what existing content does only where a player-side actor holds cards or statuses between battles; no sample moved.
- **`GameState.ComputeHash` mixes four more facts**: whether an actor is a party member, who an enemy is telegraphing against, which members have acted, and which is the active one. Each changes what happens next, so two games that differ in one must not hash the same.
- **A test names the member.** `hero Vestal hp 20` adds one with its abilities and binds it under **its own name**, so `expect Vestal.hp == 20` reads the live member rather than the printed stat on its definition. `play Cleanse by Sister on Templar`, `cast Smite by Crusader on enemy` and `pass Vestal` say who is acting; `by` may be written either side of `on`.
- **Assigning `lane` or `rank` is a move, and CT328 refuses only `position` now.** It used to refuse all three, because assigning any of them wrote a stat that the slot shadowed and nothing read: the line looked like a move, did nothing at all, and said nothing about it. There was no diagnostic of any kind. `position` stays refused, at lint and now at run: it reads a rank and always will, but it names one axis of a place that has two, and a move has to say which.
- **Coverage.** Monster Train #10 (floors), Dota 2 #6 (Crystal Nova) and Dota 2 #7 (Blink) move from *Not expressible* to *Works*, and gap 12 — space, and reaching across a board — closes: 71/9/13 becomes 75/8/10. `samples/corpus`'s Dota file declares a board and writes both effects for real; `samples/board` gains reach, the three area shapes, movement between floors, an `until` move and a unit that refuses to be pushed.
- **`State.Actors` comes back in slot order**, by `(lane, rank)`. Its own summary already claimed position order while it returned insertion order; the two agreed only because a new actor always landed past everyone.
- **One function decides what anything may be aimed at.** A card's target, an ability's, an enemy's move and the `attack` verb settle theirs through the same four filters, in the same order: the side and being alive, reach, the action's own `target … where`, then the `targetable` channel. Five sites each rolled their own, which is why an ability read no `target` line, a `where` filter was read by nothing, and `target ally` never asked. The `targetable` channel's own semantics are unchanged — base 1, above zero passes — and area and random effects still ask none of it: `deal 3 to enemies` reaches a stealthed minion, as it always has. Reach is the one filter with nothing in it yet; it is where a later release measures distance, and it is the only place that will.
- **`target ally` asks when there is somebody to ask about.** With a chooser installed and more than one living legal ally, the picker opens over exactly those candidates. It used to set the target to the party leader without asking, so a card meant for whoever needed it healed the leader while a wounded ally stood beside it — and with the leader hidden by a rule, it then refused itself rather than finding the ally. One candidate is not a choice, so a game with one actor on the player's side is unchanged, down to the random draws it does not make.
- **An ability with an unused `target` line is CT309**, as a card with one already was, and CT302 now reads the names inside a `target … where` — so `target enemy where postion <= 1` is a warning at lint rather than an error the day that line runs.
- **Every word the Godot addon gives script comes from a written-out table.** Nine of them — an entity's `kind` and `team`, a diagnostic's `severity`, a description's `level`, an event's `phase`, a listener's `limit`, a modifier's `layer`, and the result of an action — were made by lower-casing a C# enum member's name. Renaming a member would have silently changed what a game's script compares against, and a member of two words would have arrived run together: add `NotYourTurn` after 1.0 and `Play` starts answering `notyourturn`, which is neither snake_case nor a word anyone chose. Each table refuses a member it has no word for instead of guessing.
- **The node's own loop is no longer callable from GDScript.** Godot's source generator publishes every method of a `[GlobalClass]` to script whatever C# calls it, so `Guard`, `AfterAction`, `SyncChoice`, `Word`, `Refused` and `BattlePresenter.Pump` were all published — and at 1.0, published means promised. `r.call("AfterAction")` re-entered the event drain and told the game every buffered event a second time; `r.call("Word", 0)` froze the *ordinal* of an enum member to a word, so reordering the enum would have changed a published method's answer. They are on private nested classes now, which the generator does not scan.
- **`TrackedStats` is read live everywhere it shows.** Set after the rules exist, it used to stop affecting an event's `after` — the host had captured the list when the runtime was built — while still affecting the `stats` of a choice's options, which read it live. One export meant two different things depending on which dictionary you were looking at.
- **A `TickDriver` is put on its runtime's `TicksPerSecond`**, with a warning naming both rates, as the runtime enters the tree. Two exports held the same number with only a doc comment saying they must match, so a driver left at another rate made `cooldown 8s` mean two different lengths of time, silently.
- **A zone the rules do not know is said out loud.** `AddCard("Guard", "hnd")` returned a real id and put a real card in a pile nothing will ever draw from, answering no differently from the zone you meant. The rules deliberately take any string, so a game can still invent a zone; `AddCard` and `GetZone` now name the eleven they know in the Output panel when given anything else.
- **`GetTargetMode` answers `""` for an id that names nothing**, where it used to answer `"none"` — identical to a card that needs no target, so a UI could not tell a stale id from a real answer.
- **`BattlePresenter.DefaultFormat` calls the addon's own event mapping** instead of rebuilding all thirteen keys by hand. The runtime node always installs the real one, so the copy only ran for a presenter used standalone — exactly where a key that had drifted would go unnoticed.

### Documentation

- **The `of` scope rule is written down**, with a table of which end of an action each channel means, in `docs/language.md`'s Modifiers section. The old sentence — "the modifier applies when the value being computed belongs to someone in the group" — was true and useless, because nothing said which end "belongs to" meant. It is what misled the author of the reference game into shipping a relic that did nothing.
- **The save example in `docs/csharp.md` has a run above the battle.** `SaveFile` carried `Fingerprint` and `Game` and nothing else, which is a save for a game with no run at all — for no roguelite. It now has the `Run` field, with three sentences on why the file is a pair and what happens when the two halves drift.
- **`State.ComputeHash()` is named.** The guide recommended comparing state hashes three times and never said what to call; `runtime.State.Hash()` does not exist, and the only way to find the real name was to read the Godot addon's source.

### Fixed

- **One entity answers the group words.** `.count`, `.first`, `.last`, `.empty` and `.any` work on a single entity as they do on a group. `choose 1 from hand as picked` binds an entity where `choose 2` binds a group, so `picked.first` used to fall through to "a stat nothing has" and read 0 — on the one-card path, which is the path an author tries last.
- **`modify damage: -stacks` described as "Damage dealt +-stacks"**, because a negated name is not a negative literal. It reads "Damage dealt -X." now, as `+stacks` reads "+X".
- The Godot dock's Tests tab clipped its own summary to a few pixels at every width, so "3 passed, 1 failed of 4 block(s)" read as "3".
- **A call from a Godot `BattleEnded` handler no longer crashes the game.** The node recorded the end of a battle *after* telling the game about it, so a handler that acted came back round to a check that had not yet noticed, told the game again, and died 789 frames deep in a stack overflow with no diagnostic. Reads were fine and writes were fatal — the hardest kind of rule to learn by accident, on the most obvious line a game will ever write. Handing out the reward in the handler, taking the gold and starting the next battle are all ordinary now, and a battle a handler starts tells its own end when it comes. `docs/godot.md` has an **Acting from a signal** section stating the rule, including that the handler runs while the winning play is still returning.
- **CT306 no longer calls `on killed: gain 2 gold` a loop.** `gain`, `lose` and `change` cover a resource and a status with one word, so the verb table had to list a death and a status applied for all three; the cycle check now reads the word the line names, and only `hp` kills. A folder where several relics pay out on a kill printed one of these each, which is how a note teaches a reader to ignore the code it is filed under — and it was masking a genuine cycle in `samples/corpus`, which is now reported.
- **`cantrip sim` no longer reports a card tagged `unplayable` as never playable**, and spells a bare enemy name in a battle label the way its declaration does. A curse is never playable on purpose, so it was the one line in the one report meant to hold whoever plays that could never be acted on; and `battle "Bell Warden", Tidewalker` printed as `Bell Warden + tidewalker` while the hp table under it said `Tidewalker`.
- **A group answers `zone`, `controller` and `name`** the way it already answered `lane` and `rank` — from the first of them. `log created.zone` printed `0` and `created.controller.name` failed with `` `0` has no property `name` ``, because both fell through to the stat sum, where a stat nothing has is 0.
- **`play X by Y on Z` was read as a status.** `on` is an operator and `by` is a clause, so the aim landed inside the clause's own value and the linter reported the performer as an undefined status (CT302). It is an aim in either position now.
- **A listener's `source` is the listening entity, not the event's source**, and nothing said so. A relic that wants to know which member played the card reads `event.source`; `source` there is the relic. The rule is unchanged and always was — it is now written down, in [coverage](docs/coverage.md)'s sharp edges, because the party is the first thing that makes the difference visible.
- **`adjacent` described the wrong side of the board.** The phrase table hardcoded "adjacent enemies", so `modify attack of adjacent(self): +1` on a player's minion described itself as "Attack +1 for adjacent enemies" — the buff handed to the other side, in the generated text of a card that ships in `samples/corpus`. It now reads the side the anchor is on: "the allies beside itself" on a minion, "the enemies beside the target" on a card that targets an enemy, and "the ones beside …" where the side genuinely cannot be told, as on a status either side could be holding.
- **A card's `target … where` was not printed at all.** Pike read "Deal 5 damage" and said nothing about the half of the card that decides what it may be pointed at — correct, and silent about the whole rule. It reads "Targets an enemy in the front 2 ranks." now, in the board's own words for a rank.
- **A group of one did not know where it stood.** `created.rank` read 0 while `created.first.rank` read 2 — the same actor, two answers, no message — because a place fell through to the stat table, where nothing has a `rank`. A group now answers `.lane` and `.rank` for the first of them in board order, so a group of one answers like the one it holds.
- **A freed slot is reusable, so an adjacency aura works across a death.** A dead actor leaves the board for the `dead` zone, and its slot is genuinely free: the next summon fills the hole instead of landing past it. `create` used to assign one past the highest live slot, so the row grew without bound and the hole stayed — which silently broke Hearthstone's Dire Wolf Alpha, listed in [coverage](docs/coverage.md) as *Works*. With a minion standing behind a corpse, the one summoned to replace it landed two slots from the wolf and got no buff, with no message anywhere. Survivors still never shift; `on_vacated close_ranks` is opt-in.
- **An `ability` reads its `target` line.** `cast Smite` on an ability declared `target enemy`, with nobody named, used to run the effect at nothing and report that it had played — no damage, no error, no clue. It now settles a target exactly as a card does: one candidate is taken, several open the picker, only legal candidates are offered, and a taunt narrows them. An ability with nothing legal to aim at answers `InvalidTarget` and does not start its cooldown.
- **A card's `target … where` filter was read by nothing at all.** `target enemy where it.hp <= 10` parsed, loaded and linted clean — and left the card with no target mode whatsoever, so it asked for nobody and its effect resolved at nothing.
- **Pike's rules text said the opposite of the rule.** `modify targetable of enemies where card:Pike, it.position > 1: set 0` described as "Targetable is 0 for ALL enemies", dropping both conditions that carried the whole meaning. Writing the reach on the `target` line removes the modifier and the sentence with it; printing the reach itself is still to come.

### Breaking changes and save format

- **Breaking changes, in content.** The five refusals above (CT320 on `replay` and `create`, CT322, CT323, CT324) reject content that used to load, and each rejected line did nothing or something other than it said. Enemy moves and `attack` now ask the `targetable` channel. `ScheduledSnapshot.Block` is now `BlockAddress` and `Deadline` is now `UntilEvent`: both old names remain as write-only properties, so an older save still restores, but code reading either from a `GameSnapshot` must use the new name.
- **`IDefinitionChooser` is gone.** Its one member, `ChooseDefinition`, is now a default member of `IChoiceProvider`: a chooser that answers offers such as `discover` overrides it, and one that does not gets the first candidate. A chooser that implemented only `IChoiceProvider` was never asked, so every `discover` silently took option one, with no error at compile time or run time. Drop `, IDefinitionChooser` from your chooser's declaration; nothing else changes.
- **`PlayResult` is now `ActionResult`, and `StartBattle`, `EndTurn`, `Execute` and `UseAbility` return it** instead of `void` and `bool`. Every call that can stop for a choice now says so the same way, by returning `ActionResult.ChoicePending`, so a game that checks what `Play` hands back no longer has to remember that the others report it elsewhere. `UseAbility` answers `Played`, `NotReady`, `NotACard` or `ChoicePending` instead of one `false`. `ActionResult.NotReady` is new: an ability still on cooldown. An ability has no cost and does not settle its own target, so `UseAbility` never answers `NotEnoughEnergy` or `InvalidTarget`; both are in the type for the day it does. The Godot node's `use_ability` widens the same way, below.
- **Narrowings that stop being possible after 1.0.** `Ruleset.Default` is now the method `Ruleset.CreateDefault()`: each call allocates a ruleset of its own, which the property's name hid, so `Ruleset.Default.HandSize = 99` set a field on an instance nobody kept and was silently discarded. `Rng.GetState` and `Rng.SetState` take and return `ulong[]` — the shape `GameSnapshot.Rng` already uses — instead of a four-element tuple whose arity could never change; `Rng.StateWords` says how many words, and `SetState` refuses an array of any other length rather than half-restoring. `Num.FromInt` throws `ArgumentOutOfRangeException` past ±9,223,372,036,854 instead of wrapping round: `Num.FromInt(long.MaxValue).ToInt()` used to be `-1`, and every `int` is inside the range, so the implicit conversion is unaffected. `CardRuntime.Chooser` and `Interpreter.Chooser` throw `ArgumentNullException` on null instead of quietly putting a `FirstOptionChooser` in its place.
- **`Entity.Tags` and `Entity.Attached` hand out read-only views** instead of the entity's own `HashSet` and `List`. Casting one back and mutating it changed the game without telling the state, so the modifier cache went on serving the old number; that now throws `NotSupportedException`. Use `AddTag` and `RemoveTag`. Measured at no cost: the simulator's median run time over six interleaved pairs is unchanged.
- **The tree is not an extension point, and neither is the pump.** The abstract syntax nodes — `Node`, `ExprNode`, `StatementNode`, `DeclarationNode`, `MemberNode` — have `private protected` constructors, because a node type the interpreter has never heard of throws when it runs; every concrete node is sealed, as it already was. These are internal, having been public only because a test or the simulator needed them: `Cantrip.Testing.SetupSession`, `Cantrip.Content.Scenario`, `Cantrip.Diagnostics.Suggest`, `Chain.NewRoot`, the setter of `ModifierPipeline.Evaluator` (setting it to null stopped every modifier applying, silently), `Interpreter.Applies` and `Interpreter.Amount` (now implemented explicitly on `IModifierEvaluator`), and `ExpireTimedStatuses`, `ResetResources`, `AdjustStatusStacks`, `ShuffleZone`, `ShuffleDiscardIntoDraw` and `IsBuiltinVerb`. The stepping API the Godot debugger drives, `GameState.Become`/`Duplicate` and `Interpreter.Copy`/`Transform` stay public.
- **Breaking changes, in the Godot addon.** The node's script surface is frozen at 1.0 and GDScript reports nothing until the line runs, so each of these is a change that could only be made now.
  - **`GetHand()` is gone.** Write `GetZone(PlayerId(), "hand")`, which is all it ever was. The moment a party exists, "the hand" is a question with more than one answer, and it would have gone on returning the leader's — right for one game and silently wrong for every other. The call now fails with `Nonexistent function`.
  - **`UseAbility` answers a word, not a bool**, and the same words `Play` does: `played`, `pending`, `not_ready`, `not_enough_energy`, `invalid_target`, `cancelled`, or `not_a_card` for an id that is not an ability that can be used. One `false` used to stand for a cooldown, a question the rules had stopped to ask, and an id naming nothing, so a real-time game could not tell the player why nothing happened — and `if not rules.UseAbility(...)` would have kept compiling and quietly inverted.
  - **`Save()` returns a dictionary**, `{accepted, reason, message, save}`, the shape `LoadSave` already answers with; `reason` is `"resolving"` or `"reload_pending"`. It used to throw, which from GDScript is a stack trace in the Output panel and a bare `null`: the message saying which of the two had stopped the save was the one thing a save button needed and the one thing thrown away. `CanSave()` stays, for greying the button out.
  - **`LoadContent` returns a report, and `ReloadContent` and `ContentReloaded` carry the same one.** `{ok, errors, warnings, diagnostics}`, plus `rebound`, `missing` and `ruleset_changed` for a reload. Loading answered a bare array, so every caller wrote the same scan for a severity of `"error"` before it knew whether its game had content to play, while the addon's own debugger channel already answered that with a flag. The `ContentReloaded` signal carried only the diagnostics — less than the method it announces returned.
  - **A choice request says `mode`, not `kind`, and an offer's `option_ids` count from 1.** `kind` already meant three other things inside that one dictionary, so `options[i]["kind"]` spoke a different vocabulary depending on the request. And an offer's options were the positions `0, 1, 2`, while 0 is "no entity" everywhere else an id crosses: answer code that filtered 0 out — the obvious thing to write — dropped the first candidate of every `discover` and said nothing.
  - **`SpawnEnemy`'s "use the content's health" is `-1`, and 0 is refused.** 0 used to mean the content's health, so a game that worked one out and arrived at 0 got a full-health enemy instead. Passing 0 now fails with a message naming `-1`, rather than being read as either thing.
  - **`ApplyStatus` and `GrantAbility` fail one way.** Both answer 0 for an unknown target or owner **and** for a name no content defines. An unknown name used to throw, which from GDScript is `null` and a stack trace, so a caller checking for 0 — which is what the guide told it to do — was right half the time.
  - **`cost` and `result` are always there.** A description carries `cost` as `null` when the entity has none, and a refused `AnswerChoice` carries `result` as `""`. Both keys used to be simply absent, which forces a `has()` check a reader does not think to write and reads as an empty dictionary when they do not.
  - **`ContentManifest` is gone.** An unused `[GlobalClass]` with no reference anywhere in the repository, it defined a global GDScript class by that name in every project the addon was installed into, colliding with any game that has a content manifest of its own — permanently, once 1.0 freezes the name.
  - **Parameters are snake_case**, in signals and methods both: `effect_event`, `card_id`, `target_id`, `max_energy`, `draw_opening_hand`, `owner_id`, `self_id`, `request_id`. Method names keep their C# form, as they always have. Godot generates a signal handler from the parameter's name, so connecting `EffectEvent` in the editor wrote `func _on_effect_event(effectEvent: Dictionary)` — camelCase leaking into a script where nothing else has it.
  - **`Seed` is a 64-bit integer, and every value is a seed.** It was a 32-bit export clamped with `max(1, seed)`, so 0, 1 and −5 all played the same game and nothing said so, while GDScript's own integers are 64-bit.
  - **`ContentFolder` defaults to the `cantrip/content/folder` project setting**, and to `res://content` when that is unset. The dock read the setting and the node did not, so a project that moved its content got a dock linting one folder while the game loaded another, with no complaint from either. The plugin now also registers all four `cantrip/*` settings, so they appear in Project Settings instead of having to be typed in from the documentation.
- **Save format.** Saves are now **format 3**, which carries the board: `BoardName` and `Board` on the save, and a `Lane` on every entity beside the `Position` that is now its rank. Every 0.1.0-preview.5 save still loads — a format 2 save was played on one lane with no floors, which is exactly the default board, so the upgrade gives everyone lane 0 and the default board and moves nothing else. There is a preview.5 save checked into the tests and restored on every CI run. `MinimumReader` moves to 3 with it, because a format 2 reader handed one of these would put every actor in lane 0, which is getting the game wrong rather than missing a field it never knew about. A patch that **reshapes** a board refuses a save only when a saved actor stands outside the new bounds, naming the board, both shapes and where that actor was standing; growing a board loads fine and nobody moves. A save whose board the loaded content no longer declares is played on the shape the save itself carries, so an edit never strands a save.

  Format 2 was the release that made "an older save still loads" true rather than merely unbroken. `Restore` used to refuse any format that was not exactly its own, so the first release to bump the number would have broken every save before it; it now refuses only a save that needs a newer reader and upgrades anything older, and the Godot node and `SaveEnvelope` do the same. A save made here is refused by preview.5 with a clear message instead of being restored with its waiting work silently dropped.
- **Every turn-shaped call refuses on a tick runtime.** `EndTurn`, `Pass`, `CanAct` and `ActiveMember` on `CardRuntime`, and the same four on the Godot node, throw with a message naming `Tick()` — the mirror of what `Tick` has always said on a turn runtime. `EndTurn()` used to run a complete turn cycle, every enemy's telegraphed move included, in a game with no turns: a front end that left its **End turn** button wired up, which is the default in every sample and every doc snippet, gave the player a button that fired every enemy's move at once for free. `IsRealTime()` on the node is there so a shared UI can ask before it draws one.
- **CT337, CT338 and CT339 are errors**, so content that says `clock ticks` and lints clean today may stop. Every one of them is a declaration that never ran.
- **`ScenarioRunner.Run` and `Replay` throw** on content whose ruleset says `clock ticks`, and `cantrip sim` exits non-zero on such a folder.
- **`modify <channel> of <group>` now names whoever the value belongs to.** Which end of an action that is, the channel decides, and it is the same end the bare form uses: `of party` on `damage` is what the party deals, `of party` on `damage_taken` is what it takes. Before, `of` was matched against the query's subject on every channel, so on `damage` it meant the *target* while the bare form meant the source — two spellings that read as widenings of each other, scoped to opposite ends of the same hit. `modify damage of party: +2`, the line a party game is most likely to want, matched nothing at all and said nothing about it; and `modify cooldown of <anybody>` could not match either, because there the subject is the ability rather than an actor, so "your abilities recharge faster" could not be written for a party. Content that wrote `of enemies` on `damage` to mean "damage landing on an enemy" now says `of allies`, `of party` or `of player`; three lines in `samples/corpus` did, and their own tests caught all three.
- **`create` and `copy` read `to` as whose it is, not as which pile.** `into` is the pile, `to` is the recipient — as `to` is for every other verb in the language — and `onto` is still a second spelling of `into`. `create Brine into discard to leader` in an enemy's move now puts the curse in the *player's* deck. Before, all three words meant the pile, so `to` was parsed and thrown away and the curse was made in the enemy's own discard: a card that reads as one thing and does another, which is the thing CT323 exists to stop. `create Shiv 2 to hand` is now refused by name, saying to write `into`.
- **`CardRuntime.Player` is no longer nullable**, and throws before `CreatePlayer` with a message naming the call to make; `HasPlayer` is the question to ask where that is genuinely in doubt. The guide wrote `runtime.Player` bare in five places, and in any project with `WarningsAsErrors=nullable` — which this repository's own `Directory.Build.props` sets — every one of those was a build error.
- **`RuntimeOptions.Seed` is `long`.** Any 64-bit number is a seed of its own, 0 and negative ones included, which is what the Godot guide already promised and what the node's own export always was. `new RuntimeOptions { Seed = 12345 }` compiled only because it was a literal: every host that seeded a run from a number it had computed wrote `(ulong)(uint)seed`.
- **Breaking changes, in generated text.** `DescriptionBuilder.DescribeMove` gained a trailing optional parameter, who the move is aimed at: source-compatible, but a game compiled against an earlier build needs a rebuild. And an enemy move written `to target` reads "Deal 8 damage." where it read "Deal 8 damage to the target.", with the target named in `Against`, `target_name` and `line` instead. A game that draws the text is unaffected; a game that pinned the string moves.
- **Breaking changes, in targeting.** `UseAbility` can answer `InvalidTarget`: an ability that declares a `target` line with nobody legal to aim at is refused instead of running at nobody. It was documented as something `UseAbility` never answers; it does now, in C# and as `invalid_target` from the Godot node. A game that treats anything but `played` as a failure needs no change; one that switched exhaustively on the old set does. `CardRuntime.LegalTargets(Entity card)` is now `LegalTargets(Entity action)`, and `TargetMode(Entity card)` is `TargetMode(Entity action)` — both have always accepted any entity with a definition and now genuinely answer for abilities, so the name was a lie in an API about to be frozen. Only a call that passes the argument by name is affected.
- **Breaking changes, on the board.** `Interpreter.Create` and `Interpreter.Copy` return `Entity?` instead of `Entity`, because a summon into a full lane makes nothing. `CardRuntime.StartBattle` takes a third optional argument, `board`. `EntityView.Position` is a read-only alias for the new `EntityView.Rank`, and the Godot node's entity dictionary carries `lane` and `rank` beside the unchanged `position`.
- **Same-seed results, the tick clock.** `turn_start` and `turn_end` do not fire on a tick clock, and `State.Turn` stays at 0. `turn_start` used to fire once per real-time battle, at `StartBattle`, while CT335 — the one diagnostic whose whole job is to explain how real time differs from turns — told authors it never fired at all. Content written against the diagnostic got one reset of every `reset_on turn_start` resource and one pass of every `turn_start` listener that it did not expect; content written against the engine got a rule the linter refused to let it state. The diagnostic was the honest half. The opening hand is still dealt at `StartBattle`, because a hand is not a turn. `SpawnEnemy` also raises `created` now, so a game whose content listens `on created(kind:actor)` hears the enemies its host spawns. No sample moved.
- **Same-seed results, the party.** A game with no `hero` is unchanged byte for byte: `cantrip sim samples/slice` over 500 seeds gives the same 70.8% cautious and 74.0% patient, with every per-battle row and every hp total identical. A game whose player-side `actor` holds cards or carries statuses between battles will see those cleaned up now, where they used to persist.
- **Same-seed results, reading and writing a place.** Three reads change answer for content that was already written. A group's `.lane` and `.rank` used to be 0 and are now where the group stands. Writing `who.lane` or `who.rank` used to do nothing and now moves the actor; writing `who.position` used to do nothing and is now a runtime error. All three were either CT328 or read 0 with no diagnostic at all, so no content that lints clean today is affected.
- **Same-seed results, on the board.** A freed slot is filled where a summon used to land past it, and actors act in slot order. Content that never summons an actor is unaffected: `cantrip sim samples/slice` reports 70.8% cautious and 74.0% patient over 500 seeds, as it did, down to every figure in the hp breakdown, because that sample's only `create` makes a card. Content that summons after a death will play differently from 0.1.0-preview.5, and correctly. **Every state hash has also moved**: `ComputeHash` now mixes each actor's lane and rank and the board's name and shape, because two games on different boards have different futures. A hash is only comparable within one version of Cantrip, as [stability](docs/stability.md) says.
- **Same-seed results.** A `target ally` card with several living allies and a chooser installed now opens the picker where it used to take the leader, and an ability with a `target` line now settles one where it used to run at nobody. Both can change how a game plays out from the same seed. Neither moves any sample: no sample has a second actor on the player's side, and every sample ability is cast with a target. Otherwise unchanged — the simulator plays the same seeds identically, and `describe` over every sample folder is byte-identical apart from the text fixes above.
- **Bot behaviour.** Unchanged. `cantrip sim samples/slice` reports 70.8% cautious and 74.0% patient over 500 seeds, as it did in 0.1.0-preview.5, and the full report for both bots — hp, damage mix, turns, plays — is identical line for line. The bots ask the engine what is legal rather than working it out again, so they follow the new rule wherever content uses it; `samples/slice` has no ally target, no ability and no target filter for it to bite on.

## [0.1.0-preview.5] - 2026-09-24

### Added

- **`copy`: duplicate something that is in the game, as it stands.** `create Strike` makes a Strike as it is *printed*; `copy picked` makes one as it *is*, with the buff it was given this battle and the cost it was discounted to. `copy [who] [N] [into zone]` takes the zone words `create` takes, defaults to itself, and binds **`copied`**, always a list. Slay the Spire's Dual Wield and Burst, and most of Hearthstone's board copies, are one line now instead of a fresh card that quietly loses everything the original had gained.

  Two rules decide what a copy is, and both of them are the answer to a trap. **Its side and owner come from the original**, never from whoever is copying: a player's card that copies an enemy's minion gives the *enemy* a second minion, where taking the side from the declaration would hand it to the player. And it is **placed by kind, where a new one would go** — never in the zone the original sits in, which would otherwise drop a copy of an active power straight into `powers` as a second power nobody played, and a copy of an exhausted card where nothing can reach it.

  Live stats, runtime tags and a fresh instance of every status and keyword come across, with their `stacks`, `duration` and `expires_at` as they stand. Those arrive silently: no `status_applied` is raised and `immune` is never asked, because a copy is a snapshot of a state, not a new application. Nothing is restored — a wounded minion is copied wounded, and `copied.hp = copied.max_hp` is the one visible line that says otherwise. A copy raises `created` with `event.copy_of` set to the original, so the original hears `on created(self)` about its own copying; it is in the sharp edges. An actor that has died is skipped, even when named outright, because `kill` leaves its hp alone and a copy would arrive alive and whole. `copy Strike` is refused and names `create Strike`, at lint (**CT320**) and at run. See [Built-in verbs](docs/language.md#built-in-verbs) and the recipe [Copy a card as it is now](docs/writing-content.md#copy-a-card-as-it-is-now).

- **`transform`: replace what something is while it keeps who it is.** `transform [who] into Definition` keeps the entity's id, owner, source, side, sequence, zone **and index in that zone**, its board slot and its history counters — so a `let`, an `event.target`, a test's `enemy2` and a C# reference a game has cached all still hold the same object, now wearing the new name. Polymorph, and every "becomes a different card". The workaround was `destroy` plus `create`, which loses the slot, the id and, for a generic `actor`, the side.

  Everything the old definition brought goes, and goes silently: stats, tags, every status and keyword, the spent `once per ...` windows, the intent, the phase and its own `next turn:` plans. The new definition's stats and tags take their place, so the new thing arrives whole; three visible lines carry a wound across. Statuses raise **no** `status_removed`, because one verb raising a variable number of cancellable events — each able to destroy the host half way through — is not something content could reason about, and `destroy` already sheds its attachments the same way. The one event is **`transformed`**, raised once through all three phases with the tags the entity had before and both definitions as `event.was` and `event.into`. It is not a `created`, a `died`, a `killed` or a `destroyed`, so a Polymorph never fires a death rattle.

  An actor rolls a fresh intent at once, and an `enemy` may become an `actor` declaration and back with its side kept, so one `actor "Sheep"` serves both sides. `into` takes a definition and never an entity, which is refused by name rather than quietly giving the other thing's *printed* stats, and a misspelt one there is error **CT302** with the nearest name, as `create`'s is. A `transform` inside an `until` block is refused at lint (**CT321**) and at run: `until` puts back what it did, and none of this can be put back. See [Built-in verbs](docs/language.md#built-in-verbs) and the recipe [Turn something into something else](docs/writing-content.md#turn-something-into-something-else).

- **`play`: play a card out of a pile, without the player choosing it.** `play card [on target] [, free]` — "play the top card of your draw pile", Mayhem, Monster Train's automatic plays. The card leaves its pile, pays, raises `card_played` with its tags, counts towards `cards_played` and `attacks`, runs its effect, and is filed afterwards by the tags it has *then*. It never passes through hand, so nothing is `drawn` and the hand limit is not involved. `replay` remains the other verb and is not a play: it resolves an effect again for nothing, leaving the card where it is.

  It binds **`played`** to the card, or to **`none`** when it was not played, and binds it before anything else so the name always exists. A refusal the rules allow — an empty pile, an unplayable Curse, a cost the payer cannot afford, no legal target, a card already in `play` or `powers` — is not an error, because "play the top card of your draw pile" must not crash the first time the top card is a Curse.

  `, free` changes what is **paid**, never what the card **sees**: an X-cost card played free binds `x` to what the payer has and spends nothing, and the `card_played` event's `amount` is what was actually paid, so "gain 1 hp per energy spent" stays honest. **Targeting never prompts**: a card that needs a target and was not given one has one rolled from the game's own RNG, through the `targetable` channel. A target written with `on` is used exactly as written; the running effect's own target is inherited only where the card could legally be pointed at it, because a `play` inside a listener inherits whatever that event was about and a hint the card cannot take would otherwise refuse the play silently. The roll goes through the same channel, so a Taunt binds an automatic play as it binds a hand-played one and the roll replays and saves. A nested play extends its caller's chain, so `once per chain` counts one chain across a cascade; direct recursion stops at `max_call_depth` with a message that says what happened. See [Built-in verbs](docs/language.md#built-in-verbs) and the recipe [Play a card the player did not choose](docs/writing-content.md#play-a-card-the-player-did-not-choose).

- **The Godot dock's Source tab is an editor.** Write `.cantrip` content in it, save with Ctrl+S or the Save button, and read what the parser and the linter make of it a third of a second after you stop typing: the line marked in the gutter, the message written out under the buffer as the caret reaches its line, and an **Apply fix** button that puts the suggested word in for you. **Run tests** runs the content's own tests against the buffers, saved or not. Saving writes the `res://` file and tells Godot, so the importer picks it up, and a file written with Windows line endings is saved back with `\n`. Problems, Tests and Preview read the same answer, so nothing in the dock disagrees with what is on screen. A check costs about ten milliseconds on the largest arrangement in this repository, 23 files and 1,800 lines.

  **It indents with spaces, at the width the buffer already uses, and never writes a tab**, including a pasted block, a middle-click paste, and a block dropped in from another window. The language decides where a block ends by how deep a line is and counts a tab as four columns, so one tab in a two-space file moves a line into another block without changing how it looks.

  A file changed on disk under an unsaved buffer is left alone, with one line offering to keep yours or take theirs; the warning follows the file rather than the tab, so switching away and back brings it with you. A clean buffer is simply reread. A file deleted underneath a buffer leaves the buffer alone, and Save writes the file again; a `.cantrip` file added or deleted outside the editor joins or leaves the content by itself. Switching files parks a buffer with its caret rather than asking anything, and the tab counts what is unsaved.

  It does not complete names, go to a definition, or push a save into a running game: those are the next pass. Unsaved buffers do not survive a C# build, which reloads the addon; the Output panel says so when it happens.

- Cantrip.Core's new public API, which is what the three verbs are made of: `GameState.Duplicate`, a second entity made from one that is in the game, with the stats, tags and attachments it has now; `GameState.Become`, another definition put on an entity in place; `Interpreter.Copy` and `Interpreter.Transform`, the verbs' own entry points, which raise `created` and `transformed` around those two; the event name `BuiltinEvents.Transformed`; and the codes `Linter.ContentWhereSomethingInPlayIsMeant` (CT320) and `Linter.TransformInsideUntil` (CT321). `Entity.Name` has a setter inside the library and is read-only outside it, as it was. Nothing was removed: code written against 0.1.0-preview.4 compiles unchanged.
- The three recipes are content, with their own tests, in `samples/recipes`: [copy-a-card-in-play.cantrip](samples/recipes/copy-a-card-in-play.cantrip), [play-a-card-from-a-pile.cantrip](samples/recipes/play-a-card-from-a-pile.cantrip) and [transform-into-something-else.cantrip](samples/recipes/transform-into-something-else.cantrip). CI lints and tests them with the rest of the folder, as it already did.

### Changed

- **`play` is one word that means two things, told apart by where it is written.** It was a test verb; it is now a rule verb as well. A `play` in a test's own body is the test's — it still puts a card into hand by name and plays it from there — and a `play` written anywhere else, in a card's effect or in a content verb a test calls, is the rules'. The rule is lexical rather than dynamic because a content verb takes its context from whoever called it, so no check made while the verb runs could read `verb cascade(): play draw.first` correctly when a test line calls it.

  Two diagnostics move with it. `play Strike` in a card effect was CT301, an unknown verb that "only exists inside `test` blocks"; it is now **CT320**, which says the more exact thing — a card is played out of a pile, not out of content — and names the fix. Inside a `scenario` it is still **CT301** with the message it has always had: a scenario states the fight, and a bot plays it.

- **A card played while another card's effect is resolving no longer drains the outer effect's queued triggers.** Only the outermost play drains, and only a play at the top level checks whether the battle is over. A nested play that drained would resolve the outer effect's already-queued after-listeners in the middle of that effect, which nothing else in the language does. This is visible to a game whose `IEffectHost.OnEvent` calls `CardRuntime.Play` during an action: the triggers and the battle-over check now happen when the outer action finishes rather than inside the inner play. Order is unchanged and nothing is lost.

- **A card that names the end of a pile reads it out in words.** `discard hand.first` used to generate "Discard hand.first."; it now generates "Discard the first card in your hand." The same goes for `.last`, and for `draw`, `discard` and `exhaust` — "the top card of your draw pile", "the bottom card of your discard pile" — wherever a verb names who or what it acts on, which is `discard`, `exhaust`, `move`, `destroy`, `apply ... to`, `replay` and the rest. It was the spelling read back at the player, which `replay hand.first` made obvious. `text_checked` is taken from the effect rather than from the text, so no recorded hash moved and no CT402 appears.

- **`Entity.Name` can change**, and one internal rule changed with it. `transform` renames an entity in place, so a game that caches or keys on a card's or an actor's name has to expect that name to move. `GameState.Restore` used to reuse an existing `Entity` instance only when its id, kind **and name** all matched, which silently assumed a name is fixed for the life of an entity; it now matches on id and kind and assigns the saved name. Without that, an effect that transforms something and then asks the player a question would hand the game a stale, removed object while the runtime held a new one — because a deferred choice rolls the action back by restoring a snapshot. The save format is unchanged: `EntitySnapshot` has always stored the name and the definition's name separately.

- **The docs treat Godot as the front door.** Cantrip is a Godot library first, and the docs now read that way. The [README](README.md) says in its opening that you use it from Godot 4.6 on Godot's .NET edition, in GDScript or C#, or from any other .NET project; the Godot route is first in **Where to start**, first under **Get started** — with a GDScript battle beside the C# one — and first in the documentation list, and its command-line section says which of those commands the dock already covers. The [quickstart](docs/quickstart.md) sends a Godot reader to [the addon guide](docs/godot.md) before its first step and says plainly that it is the route for a game that is not in Godot. [Using Cantrip from C#](docs/csharp.md) opens by saying a Godot game needs none of it. [Writing content](docs/writing-content.md), [the language reference](docs/language.md), [Simulating](docs/simulating.md) and [samples/README.md](samples/README.md) say where the editor dock does the work of a command and where it does not, both NuGet pages lead with Godot, and [CONTRIBUTING.md](CONTRIBUTING.md) maps the addon before the library, as the README now does for a contributor.

  What Godot costs is said in the same breath and not softened: the .NET edition of the engine for everyone who opens the project, the .NET SDK, a C# solution even in a game written entirely in GDScript, and Godot's own limits on where a .NET game can be exported. The dock's limits are stated as plainly: neither `sim` nor the REPL has a tab, so a Godot project still installs the tool for those. Nothing about the engine-free core changed. It still targets `netstandard2.1` and references no game engine, the console quickstart is still followed word for word against freshly packed packages before every release, and [docs/stability.md](docs/stability.md) remains the only place that says how much of any of this has been tested.

- The README said Cantrip does not do "two players, or an opponent with its own hand and deck". The second half was wrong: a card belongs to whoever controls it, so an enemy can hold cards and play them at the player, and hands and draw piles are per-owner. Tests now pin that. What is actually missing for a second player is the priority window, nothing being able to respond to a card while it is played, which is what the bullet now says.
- The [quickstart](docs/quickstart.md) says what a `#` line in a `.cantrip` file is, where the reader first meets one. The first content block on the page opens with a comment, and until now nothing on the page said so; [Files](docs/language.md#files) in the language reference had it, several pages later.
- `samples/corpus` writes two of its effects the way the language now says them rather than around it. Dominion's Throne Room (Regent) plays the card it chose, with `play picked, free` and then `replay played`, so the card really leaves hand and is counted; Slay the Spire's Slime Boss (Slime King) splits with `transform self into Slimeling` instead of `kill self`, so it keeps its slot and its id and nothing hears a death. [Coverage](docs/coverage.md) says what that moved: no row changes its verdict, the summary counts are unchanged, and gap 5 — effects as values — is where it was.

### Breaking changes, save format, same-seed results and bot behaviour

- **Breaking changes.**
  - Lint: `copy`, `play` and `transform` are rule verbs now, and two errors come with them. A line that hands one of them a name that is content — `copy Strike`, `play Strike` in an effect, `transform Strike into Wound` — is error **CT320**, and a `transform` written inside an `until` block is error **CT321**. Both are errors, so `lint` and `validate` fail on content they passed before. Neither is covered by `--suppress CT301`, which is what content calling verbs a game registers in C# was told to use: a CI step that passed with 0.1.0-preview.4 fails here until it also suppresses CT320 and CT321, or the content stops using those three words. Content that had a verb of its own by one of these names is left alone: both checks skip a verb the content declares or the game registers (`LintOptions.HostVerbs`, and the Godot setting `cantrip/lint/host_verbs` behind it), because that verb is the one that runs.
  - A `play` written in a content verb is the rules' verb even when a test calls it. Before, a test registered `play` over everything, so `verb cascade(who): play Strike on who` put a Strike into hand and played it from there; now the same line is asked to play a card out of a pile, finds a definition instead, and fails the test — after failing `lint` with CT320. Rename the verb's own word, or write the line the way the rules read it.
  - A card played while another card's effect is resolving no longer drains the outer effect's queued triggers, and no longer checks whether the battle is over; both happen when the outermost play finishes. A C# game whose `IEffectHost.OnEvent` calls `CardRuntime.Play` during an action sees the outer effect's after-listeners, and the end of a battle that inner play won, at the end of the outer action rather than inside the inner play. Order among them is unchanged and nothing is lost. The Godot node refuses an action from a host callback, so no GDScript game is affected.
  - `Entity.Name` can change, because `transform` renames an entity in place. A game that caches or keys on a card's or an actor's name has to expect that name to move.
  - Rules text: a verb that names the end of a pile reads it out in words, so `discard hand.first` describes as "Discard the first card in your hand." rather than "Discard hand.first." A test that compares an entity's generated text sees the new wording, and a translation (an `IDescriptionLocalizer`) that supplies its own words needs the new phrases `who.hand.first`, `who.hand.last`, `who.pile.top` and `who.pile.bottom`; one that does not supply them falls back to the spelling, as today. No `text_checked` hash moved, because the hash is taken from the effect and not from the text.
- **Save format.** Unchanged: saves made with 0.1.0-preview.4 load, and the format number stays 1. Nothing this release added is written to a snapshot. A copy is an ordinary entity, and a transformed one is the same entity wearing another name and definition, both of which `EntitySnapshot` has always stored separately. `GameState.Restore` now reuses an existing `Entity` instance on id and kind alone and assigns the saved name, where it used to require the name to match too; that changes which C# object a game is left holding, never what is on disk.
- **Same-seed results.** Unchanged for the same content, seed and inputs. Nothing on a path that existing content takes rolls differently: `test` over `samples/basic`, `corpus`, `slice`, `abilities` and `recipes` prints output identical to 0.1.0-preview.4's, and `sim samples/slice --runs 200` prints an identical report apart from the wall-clock seconds in it. Content written for this release does roll: `play` settles a target it was not given from the game's own RNG, through the `targetable` channel, so a card that plays another card spends rolls where nothing spent them before.
- **Bot behaviour.** Unchanged: nothing about what a bot tries, how it scores a position or how it spends the dice changed, and 200 runs of `samples/slice` give both default bots the same tables, the same meter and the same levels as 0.1.0-preview.4 over the same seeds.

## [0.1.0-preview.4] - 2026-09-23

### Added

- A `scenario` declaration, beside `test`: a whole run stated once — a deck, some fights in order, and whatever happens between them — for a bot to play many times. Its body is statements, as a test's is, with three lines of its own: `battle "Cinder Imp", "Frost Wisp"`, `runs 500`, and an `expect` that measures every run rather than one game (`expect no stalls`, `expect wins >= 55%`). See [Scenarios](docs/language.md#scenarios).

  `validate` counts the scenarios in a folder and `lint` checks them as it checks a test, so a misspelt card, relic, ability or enemy is the same error, CT302. Three new codes: CT317, a warning, a scenario with nothing to fight; CT318, a note below 100 runs, where the same content answers differently each time, and an error when the count is not a whole number of one or more; CT319, an error, an `expect` a scenario cannot check. CT301 now names the block a verb belongs to in both directions, so `play` in a scenario and `battle` in a test each say where the line should live. A file with a `scenario` in it does not load in 0.1.0-preview.3, which reads the word as error CT0012.
- `cantrip sim <path>...` plays those scenarios, hundreds of times each, and reports what happened over them: a run that threw, with the seed and the statement to replay it; a battle that reached the turn limit; a card that was held and never playable, or never drawn; an enemy move that never fired; and, where nothing the scenario rolls changed an outcome, that every run came out the same way. What happened at least once happened in the content, whoever plays; what never happened is bounded by what the bots reached, and the block itself says so. A card drawn or created part way through a turn counts as having reached a hand and, if it was played, as having been playable, because the engine raised an event saying so. Its options are `--name`, `--runs`, `--seed`, `--bot`, `--turn-limit`, `--watch SEED` and `--suppress`, and it exits 1 on a content error, no scenario to play, a run that threw, a battle that stalled or an expectation that failed. See [Simulating](docs/simulating.md).

  **Three bots, and two of them play by default.** `cautious` tries every legal play and ability through the engine — capture the game, make the play, end the turn so the enemies answer, score what is left, roll back — and then makes the best play it found; `patient` does the same scoring two turns out, and is there to disagree; `random` is the floor and the fastest way to fuzz. `--bot cautious|patient|random|both` chooses, and `both` is the default. Each bot plays every run, from the same seeds, and the report keeps a table per bot apart from the block of facts, which is one block for all of them: a move either bot reached is a move the content reached.

  None of them knows a card, status or enemy by name, and all of them weigh a position the same way — the player's hp against the enemies' — so all three are wrong in the same direction about a card that draws and about anything that pays off several turns later, and two agreeing is not evidence. Their levels are printed under a heading that says not to quote one: on `samples/slice`, over the same 500 seeds, the cautious bot finishes 70.8% of the runs, the patient bot 74.0% and the random bot 0.6%. `expect wins`, `expect hp_left` and `expect turns` are still reported as not checked for the same reason; `expect no stalls` and `expect no errors` are checked, because they hold whoever plays. There is no option for how far a bot looks ahead and no way to tell it what a status is worth: both were measured, both move the answer by tens of points, and neither has a defensible setting.

  Nothing a bot merely tried is counted. A play tried and rolled back raises the same events as a real one, so while a bot is trying one the run records no enemy move, spends none of the scenario's `answer` lines, and reseeds the dice, so the lookahead cannot read the roll that is about to decide the play. Two bots cost about twice as long as one: the slice's 500 runs take about 30 seconds with both, about 14 with `--bot cautious` and under 2 with `--bot random`. From here on this changelog carries a **Bot behaviour** line whenever a release changes what a bot does.
- **The meter**, under each bot's table: what the engine raised while the game was really being played. Where the damage the enemies took came from, by the card or status or enemy that dealt it; the same hits by the tags they carried; what took the player's hp; and the healing, block, statuses, cards and enemy moves beside them. Every amount is one the engine itself set — a `damaged` event carries the hp actually lost, after block and capped by the hp that was left — so given the plays that were made, that is where the hp went, for anyone who made them. Which plays were made is still the bot's, which is why there is one meter per bot.

  The tag column is what makes it answer a question about content rather than about play. On `samples/slice` it reports that no tick of Burn ever carried `attack`, so `modify damage where tag:attack` would have reached none of the damage Burn dealt — and Burn's share of that damage is large: 37.6% of what the cautious bot's plays dealt and 48.2% of what the patient bot's dealt. The share is a fact about the bot as much as about the deck, so the report prints it inside that bot's block and never on its own.

  A card the tool cannot judge is named rather than guessed at: a `choose` or `discover` part way through an effect is answered at random, counted with the line that asked, and reported as such, because a bot looks one play ahead and not into the middle of one.

  The meter counts none of it either, and that is the whole of its correctness. Over 200 runs of the slice the plays the cautious bot tries and rolls back raise about 1.18 million events against 91 thousand in the play that counted, so a meter that counted them would be out by an order of magnitude. The guard is checked from the engine's own side: for every actor, the damage counted less the healing counted has to equal the hp it actually lost.
- `Cantrip.Testing.SetupSession`: the setup half of a `test` or a `scenario` — the verbs `enemy`, `player`, `hand`, `deck`, `discard_pile`, `relic`, `seed`, `answer`, `realtime` and `grant` registered on a runtime, and the statement loop that runs a line. `DslTestRunner` and `cantrip sim` share it, so a setup line cannot mean one thing in a test and another in a scenario.
- The rest of Cantrip.Core's new public API, which is what a scenario is made of: `ContentLibrary.Scenarios` and `Cantrip.Content.ScenarioDefinition`; `Cantrip.Syntax.ScenarioDeclNode`; `Cantrip.Content.Scenario`, holding the verbs a scenario body may use and the measurements its `expect` may name, which the linter and whatever plays a scenario both read, so a word cannot be legal in one and unknown in the other; and the codes `Linter.NothingToFight`, `Linter.RunCount` and `Linter.UnknownMeasurement`. Nothing was removed or changed: code written against 0.1.0-preview.3 compiles unchanged.
- Godot: the editor's syntax highlighting knows `scenario`, so a scenario block reads like a `test` block rather than like prose. Nothing else in the addon changed.

### Changed

- The README says what Cantrip is for more exactly: the combat of single-player turn-based games, cards optional. `samples/abilities` is new and shows a fight with no cards in it, run by CI like the other sample folders.
- `samples/slice/sim.cantrip` and `samples/abilities/sim.cantrip` state each folder's fights as a scenario, and CI plays both.

### Removed

- The `cantrip-sim` program, which played whole runs of the slice over a tower written in C# rather than in content. `cantrip sim` covers what it covered and states the gauntlet in content instead; what it had beyond that was a reward offer after each battle, a branch at floor 3 between the elite and a rest, and per-card and per-relic tables comparing the runs that took one with the runs that did not — which the bot decided both sides of, and which were the most quotable things in the report and the least defensible. `src/Cantrip.Sim` is now a library, shipped inside the `cantrip` tool, holding the scenario runner, the bots and the meter. It was never packed or installed on its own, so nothing a game depends on changes.

### Breaking changes, save format and same-seed results

- **Breaking changes.**
  - A whole number before a name in a setup line now repeats it: `deck 4 Zap, 4 Ward` puts eight cards in the draw pile. Before, the number was dropped with no word from anywhere, so the line put in one of each and the test measured a different deck from the one it was written as. It reads the same way on `deck`, `hand`, `discard_pile`, `relic`, `grant` and `answer`, in a `test` as well as a `scenario`. A number that is not a whole count from 1 to 1000, and a count with no name after it, now fail the line rather than being ignored. No sample or test in this repository wrote a number on such a line; content elsewhere that did will hold more cards than it did before, and a test that measured the smaller deck will fail.
  - `cantrip validate`'s summary line counts scenarios too: `2 file(s), 21 definition(s), 1 verb(s), 13 test(s), 0 scenario(s): 0 error(s), 0 warning(s)`. The count is printed for content that has no scenario as well, so a script that reads that line needs the extra field.
- **Save format.** Unchanged: saves made with 0.1.0-preview.3 load, and the format number stays 1. Nothing this release changed is written to or read from a snapshot, and a `scenario` block is not a definition, so adding one leaves the content fingerprint alone and every save that loaded before still loads.
- **Same-seed results.** Unchanged for the same content, seed and inputs: nothing in the engine changed, and a setup line with no count builds exactly the game it did. Content that wrote a count on a `deck`, `hand`, `discard_pile`, `relic`, `grant` or `answer` line plays differently, because the line now puts in the cards it says.

## [0.1.0-preview.3] - 2026-09-22

### Added

- `lint` warns about three things that load without error but do nothing:
  - a line in a declaration that ends in `:` but is not `effect:`, a `move` or a listener, such as `when card_played:`, which loads as a label and never runs (CT313; the warning suggests the listener it looks like, keeping its timing, filter and limit: for `once per battle on before_damaged(target:owner):` it suggests `on before_damaged(target:owner) once per battle:`);
  - `for N turns` giving a `duration` or `refresh` status more turns than the amount applied, which it cannot (CT314);
  - a `duration` line on a `duration`, `refresh` or `both` status (CT315).

  A game that runs blocks of its own from C# lists them in the new `LintOptions.HostBlocks`, or passes `--suppress CT313` to the tool.
- `cantrip lint --warnings-as-errors` exits 1 when there are warnings; any other command refuses the option with exit code 2. CI uses it on every sample folder. In `lint` and `validate`, `--suppress` now also leaves out warnings and notes found while loading, such as CT0105, so the two combine; errors from loading are always reported.
- A qualifier can name something that is not one word by quoting it: `card:"Fire Bolt"`, `hand where name:"Strike+"`.
- `cantrip test --trace` shows what `log` statements wrote, as `[log]` lines in a failing test's trace.
- An enemy's generated rules text names the phase a move is limited to: "Split (Broken phase only): Deal 5 damage to the player." Translations can supply the new `move.enemy.phase` phrase; until they do, such moves use the English one.
- `lint` warns (CT316) about a tag with behaviour of its own written on a line of its own, such as `exhaust` or `attack` under a card, which does nothing, and suggests the whole `tags` line.
- CT304 suggests the nearest event for one written in other words, such as `turn_start` for `start_of_turn`, and CT302 suggests `owner` for `host`.
- `DslTestRunner.ConfigureRuntime` and `DslTestRunner.CreateHost`, so a game's own test suite can run content tests that use the verbs, names and functions it registers in C#.
- Godot: `RemoveCard`, `GetDefinitions`, `DescribeDefinition` and `NewRun`, for removing and upgrading cards between battles, reward and shop screens, and a new run on the same node. The debugger's trace tab starts afresh when a game starts a new run.
- Godot: with `AutoLoad` on, the node reports each content error and warning in the Output panel, one line each. Before, a running game printed nothing, and they showed only in the editor.
- `tools/godot-install-smoke.sh` runs the first battle in docs/godot.md exactly as written and checks its output against the page.

### Changed

- The documentation was reworked after a reader study:
  - The README says where to start for a C# game, a Godot game and content authors.
  - [docs/writing-content.md](docs/writing-content.md) is new: a tutorial and recipes for content authors. The recipes and their tests are in `samples/recipes`, which CI lints and tests.
  - [docs/stability.md](docs/stability.md) now has the tested platforms, a performance figure, the range of numbers, what determinism covers, and the current known limitations, which used to be in this changelog.
  - The language reference states rules it had left unstated, and the C# and Godot guides cover more of what a real game needs: presenting events in a frame loop, several battles in one run, shipping content, saves across a content patch and what happens when content fails at runtime.
  - The Godot guide has a first battle that runs as written, a full reference for the node, and its contributor material in a section of its own.
- `CardRuntime.Restore` checks everything a snapshot needs (every definition, waiting block and entity it refers to, and that no list or record in it is missing) before it changes anything, so a save it refuses, a damaged one included, leaves the game in progress untouched. It used to throw with that game half taken apart.
- `CanCapture` is false, and `Capture` throws, while an action is running, including in a host callback part way through a card's effect, where nothing is queued yet. Such a save used to succeed and hold half an action.
- `Restore` refuses work from `Execute` saved without its block hash, or naming a block that is not a `next turn:` or `in N turns:` body. `Capture` never writes either.
- `GameState.ComputeHash` counts a waiting block by what it does rather than where it was written, so a save restored after a patch that moved the block hashes like the original, and two games waiting on different statements no longer hash alike.
- Godot: `AnswerChoice`'s `reason` words are snake_case, like every other word the node gives: `nothing_pending`, `stale_request`, `unknown_option`, `duplicate_option`, `too_few` and `too_many`. They come from a fixed table, so renaming an enum can no longer change them.
- A test line that names a card, relic, item, ability or enemy that is not defined, such as `hand Strik`, is lint error CT302. It used to be a warning, or, for an enemy (`enemy Slme hp 12`), not reported at all. The test fails saying so, with the nearest name, and without the `(Parameter 'name')` that .NET added to the message.
- Godot: `LoadSave` no longer refuses a save only because the content's fingerprint differs. It restores it when the content still has everything it needs, so a patch that only adds a card keeps older saves loading, and refuses it as `content_changed`, with the rules' message, only when `Restore` does.
- Godot: `GetWon()` returns null, not false, while a battle runs and before the first battle ends, as its documentation always said.
- Godot: `CreatePlayer`, `AddCard`, `AddDeck`, `SpawnEnemy`, `GrantAbility`, `LoadSave` and `CancelChoice` fail with an error when called from a host callback, as `Play` and the other actions already did. Every call that changes the game, the actions included, now also fails from a callback that a query such as `CanPlay` or `Describe` ran, where nothing refused it before.
- Godot: the editor dock's Reload button re-reads the `cantrip/*` project settings, so a changed setting no longer needs the plugin switched off and on.
- Godot: `CantripRuntime.Execute` is documented for its supported uses, such as a rest between battles, and its limits.
- Releases: the addon README in the release zip and in AGomnes/cantrip-godot links the Godot guide as it is at that release's tag, not on `main`. `tools/package-addon.sh` and `package-addon.ps1` take the tag as an optional argument.
- Contributors: building Cantrip.Core fails, rather than warns, when its public API changes without a line in `PublicAPI.Unshipped.txt` (RS0016, RS0017). The editor run with `--cantrip-selftest` exits with 1 when one of the dock's own checks fails.

### Fixed

- Work that `CardRuntime.Execute` schedules, such as `Execute("next turn: draw 1")`, can be saved: the save holds the statements themselves. Before, `Capture` threw although `CanCapture` said it would succeed, and under `DeferredChooser`, which the Godot node uses, every later `Play`, `EndTurn` and `Execute` threw, so the battle could not go on. `CanCapture` and `Capture` now always agree.
- A `next turn:` or `in N turns:` block waiting in a save is recorded by a hash of its statements as well as its place in its definition. After a content patch, `Restore` runs the block that was saved even if the patch moved it within its definition, and refuses the save, naming the definition, if the patch changed or removed it. Before, it could silently run whichever block now stood in that place.
- A save made with this release and restored after a content patch that adds, removes or reorders a definition's `on` blocks gives each used `once per` limit and each `on every` timer back to its own listener, found by a hash of the listener, instead of to whichever listener is now at the same place, which could let a `once per battle` listener fire twice. A listener whose `on` line changed, or whose body changed as it moved, starts afresh; one whose body alone changed keeps its limit.
- A hot reload keeps what listeners remember: a `once per` listener that has fired stays used, and an `on every` timer keeps its next due time, matched as a restored save matches them. Before, editing any definition in a file let a `once per battle` listener from that file fire again.
- Under `DeferredChooser`, an action that asks for a choice no longer throws ("The snapshot needs ..., which is not loaded") after a hot reload has removed a definition still in play.
- After a hot reload of a file with a `next turn:` or `in N turns:` block waiting, even a reload that changed nothing in it, `Capture` threw although `CanCapture` said it would succeed, and under `DeferredChooser`, which the Godot node uses, every later `Play`, `EndTurn` and `Execute` threw, so the battle could not go on. Play now goes on, and a save names the same statements in the loaded content, in the definition that scheduled the block where it can. While a waiting block is one the reload changed, `CanCapture`, and in Godot `CanSave()`, are false and `Capture` and `Save()` fail with an error saying so, until the block has run.
- Generated rules text, and `AstPrinter.Print`, put a space before a unit that is a word: "for 2 turns", not "for 2turns".
- Godot: an action a script takes in an `EffectEvent` handler has its events emitted before the outer call returns, after the events already on their way, rather than held until the game's next call. `BattleEnded` for a battle such an action ends comes after all of them.
- `tools/package-addon.sh` works with a relative output folder.
- Godot: loading or reloading content, from the node or the dock's Reload button, no longer crashes at random. The addon now reads each imported content file past Godot's resource cache, where a copy the garbage collector had already let go of could be found.
- Godot: `LoadSave` no longer throws when the rules refuse a save, such as one whose waiting `next turn:` or `in N turns:` block a patch has removed. It refuses it as `"content_changed"` with the rules' message, leaving the game and any open choice untouched. A save whose game cannot be read, or is in a snapshot format this Cantrip.Core does not read, is refused as `"wrong_format"` rather than throwing.
- Godot: `Save()` fails with "Cannot save while effects are still resolving." when a host callback calls it part way through an effect, as `CanSave()` and the guide already said; it used to save half an action.
- Godot: `RegisterName` and `RegisterFunction` accept any Callable. A GDScript lambda, or any Callable with `.bind()`, used to arrive empty ("Attempt to call callable null::null"). A value that cannot be called is refused when it is registered, one that takes the wrong arguments fails with an error naming it, and registered callables are released when the node is freed.

### Breaking changes, save format and same-seed results

- **Breaking changes.**
  - Godot: the `AnswerChoice` `reason` words were `nothingpending`, `stalerequest`, `unknownoption`, `duplicateoption`, `toofew` and `toomany`. A script that compares against them needs the snake_case words above.
  - Godot: a script that stores `GetWon()` in a `bool` variable, or compares it with `false`, must allow for null.
  - Saving from a host callback part way through an effect now fails, in C# (`Capture`) and in Godot (`Save()`), instead of saving half an action.
  - Lint: a test line naming a definition that does not exist is error CT302, so `lint` and `validate` fail on content they passed before.
  - Godot: a host callback that changed the game with a setup call now fails, as does any call that changes the game from a callback a query such as `CanPlay` or `Describe` ran. The guide already said not to.
  - Godot: `LoadSave` restores a save whose content fingerprint differs whenever the rules can, where it used to refuse it as `content_changed`. A game that relied on that refusal to turn away every save from before a patch must check a version of its own.
  - Godot: `RegisterName` and `RegisterFunction` throw an `ArgumentException` for a value that cannot be called, such as a Callable whose object has been freed, which they used to accept.
  - Godot, C# only: `CantripRuntime` and `GodotEffectHost` `RegisterName` and `RegisterFunction` take a `Variant` and dispose it when done. Pass a `Callable`, not a Variant you keep using or register twice.
  - Rules text: a move limited to a phase is written with the new `move.enemy.phase` phrase instead of `move.enemy`. A translation (an `IDescriptionLocalizer`) that does not supply it shows those moves in English, as "Split (Broken phase only): ...", and a test that compares an enemy's generated text sees the new wording.
- **Save format.** Saves made with 0.1.0-preview.2 still load; the format number stays 1, and their waiting blocks and listener records are matched by place, as before. Saves gain optional fields: `ScheduledSnapshot.Statements` and `BlockHash`, and `ListenerLimitSnapshot.ListenerHash` and `ListenerDueSnapshot.ListenerHash`. A save holding work scheduled by `Execute` carries those statements as text, which run when they come due, so treat saves as trusted input ([docs/stability.md](docs/stability.md#known-limitations)); such a save does not load in 0.1.0-preview.2. A save made with this release is refused if a later patch changed or removed its waiting block, where 0.1.0-preview.2 went by place alone and could run another block; a damaged save is refused before it changes anything. In Godot, a save made before a patch that added, renamed or removed a definition, verb or resource, which 0.1.0-preview.2 refused as `content_changed`, now loads unless it needs something the patch took away.
- **Same-seed results.** Unchanged for the same content, seed and inputs: the simulator plays the same seeds identically. Play differs only after a hot reload, where a used `once per` listener no longer fires again and an `on every` timer keeps its time. `ComputeHash`, and so the Godot node's `StateHash()`, gives different values from 0.1.0-preview.2 while a `next turn:`, `in N turns:` or `until` block is waiting, so a hash recorded with 0.1.0-preview.2 will not match there.

## [0.1.0-preview.2] - 2026-09-21

### Added

- `discover` can be answered by the player. Under `DeferredChooser`, which the Godot node uses, it pauses like any other choice: `PendingChoice.IsOffer` is true, `Definitions` lists the candidates, and `CardRuntime.Answer(EntityDefinition)` replays the action with the pick. In GDScript the pending choice has `"kind": "offer"`, each option carries the candidate's name, kind, tags and rules text, and the answer is its position. The pick is remembered by identity, so reloading content while an offer is open never swaps it for another card: if the reload takes it out of the offer, the player is asked again. `RandomChooser` now picks among offers at random instead of taking the first.
- `tools/godot-install-smoke.sh`, run by CI on every push and before every release, installs the addon from its zip into a blank Godot project outside the repository, following docs/godot.md, and plays a battle from GDScript.

### Changed

- `cantrip validate` also reports the linter's errors, such as an unknown verb, so a typo like `aply` no longer passes as "0 errors". Warnings stay with `lint`. Like `lint`, it takes `--suppress`, e.g. `--suppress CT301` for content that calls verbs a game registers in C#.
- Clearer messages for mistakes made in the first hour: a declaration name with spaces is one error saying to quote it (CT0029), a line indented under a line that opens no block is one error saying which lines can (CT0030), in an effect, a test or a declaration's properties alike, and a test naming an enemy nothing defines says so and how to fix it.
- `CardRuntime.Restore` abandons a pending choice, which belonged to the game being replaced. A new action does the same with a choice left half answered, so its answers can never be read as answers to the new one.

### Breaking changes, save format and same-seed results

Added after the release, which did not call these out.

- **Breaking changes.** `cantrip validate` exits 1 on the linter's errors, such as an unknown verb, so a CI step that passed with 0.1.0-preview.1 can fail; content that calls verbs a game registers in C# needs `--suppress CT301`. Under `DeferredChooser`, which the Godot node uses, `discover` now stops for the player's answer where it used to take the first offer, so a game's choice UI must handle an offer (`PendingChoice.IsOffer`, or `"kind": "offer"` in GDScript). `CardRuntime.Restore` clears `Pending`.
- **Save format.** Unchanged: saves made with 0.1.0-preview.1 load.
- **Same-seed results.** Changed for content with `discover`. `RandomChooser` now picks among the offers at random, from its own generator, and under `DeferredChooser` the player picks, where both used to take the first offer, so the same seed can play out differently from 0.1.0-preview.1. `FirstOptionChooser` and `ScriptedChooser` are unchanged.

## [0.1.0-preview.1] - 2026-09-21

The first public preview.

### What is in it

- **Cantrip.Core** (netstandard2.1): the language, content loading with diagnostics, a battle runtime with turns, card play, enemy intents and phases, a layered modifier pipeline, events with before, instead and after phases, deterministic fixed-point maths and RNG, save and load, hot reload, player choices a UI answers mid-effect, a causality trace, generated rules text with live values, a linter and a DSL test runner.

### Changed since the private builds

- `event` and `encounter` declarations are now error CT0113, "reserved but not supported yet". They used to load as inert definitions that nothing ran.
- `CardRuntime.CanPlay`, `LegalTargets` and `TargetMode` answer "what can I play, and at what?" exactly as `Play` decides it. The Godot node's `CanPlay` and `GetLegalTargets` use them, which fixes legal targets that ignored taunt and stealth, and `CanPlay` checking energy for a card priced in another resource.
- The enums a save stores as numbers (`EntityKind`, `ValueKind`, `ScheduleTiming`) have explicit values, so reordering them can no longer corrupt a save.
- Reloading a file spelled with the other slash, such as `content/cards.cantrip` after `LoadFolder` recorded `content\cards.cantrip` on Windows, now replaces it. It used to report every definition as a duplicate and leave the running game on the old rules.

### Known limitations

As they stood at this release. The current list is in [docs/stability.md](docs/stability.md#known-limitations); the `discover` limitation below was fixed in 0.1.0-preview.2.

- Real time is experimental: the tick clock and abilities work, but no real-time game has been built with them, and `within` needs a host to supply space.
- `discover` in a game using `DeferredChooser`, which the Godot node does by default, takes the first offer instead of asking the player.
- A run of battles (map, rewards, carrying hp between fights) is host code; the language has no run structure yet.
- The Godot addon has only been installed by its author, and its live debugging, the round trip between a running game and the editor, has only been checked by hand.
